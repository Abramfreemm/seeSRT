# seeSRT 项目交接文档（Handoff）

> 记录截至 2026-09-24 的项目需求、技术决策与进度。下次继续对话时先读本文档恢复上下文。

## 1. 项目概述

- **项目名**：seeSRT
- **一句话定位**：以剧本为「标准答案」自动纠错达芬奇导出的字幕 SRT，并按剪辑师规范自动拆分换行，支持批量处理。
- **目标用户**：影视后期剪辑师（当前实际使用剪映做字幕）。
- **本地运行，Web UI 端口固定 8877**。

## 2. 已确定的关键决策（全部确认，无遗留）

| 决策点 | 结论 |
| --- | --- |
| 技术栈 | Python + FastAPI 后端，Web UI（端口 8877） |
| 模型方案 | 本地 Ollama 为主（qwen2.5/qwen3），免费 API 备选（硅基流动/智谱 GLM-4-flash） |

| 剧本组织 | **一个文件含全部集**（内部用「第一集/第二集」分隔） |
| 剧本内容结构 | 含「集标题」（如「第一集」，中文数字）+「场景编号」（如 `1-1`）+ 中英对照台词 |

| 台词库结构 | **集 → 场景 → 台词对**（标记「第 X 集」+「X-Y」场景编号） |

| 大小写来源 | **以剧本为准**（对齐命中用剧本原文，未命中不自动改、标记复核） |

| 时间轴分配 | 拆新片段时按字符数占比分配 |
| 纠错交互 | 可撤销（改回原文）、可手动修改 |
| 未命中处理 | 用户从台词库（按集/场景定位）复制粘贴正确文本；专有名词等无法确定性纠正的片段「标红 + 手动改」 |

## 4. 核心需求详情

### 4.1 需求一：剧本对标纠错

- 上传剧本 → 提取台词库（集 → 场景 → 台词对）。
- 导入 SRT → 对齐 → 以剧本为准修正大小写/拼写/漏词，保留时间轴。
- 完整度检查：缺失台词 / 多余片段 / 低置信度告警。
- 纠错可撤销、可手动修改。

### 4.2 需求二：台词库结构化（集 → 场景 → 台词）

- 上传剧本后，自动识别并输出**每一集、每个场景的所有台词**。
- 只保留：集标记（「第一集」）+ 场景标记（「1-1」）+ 台词文本。
- 过滤：角色名、舞台提示、其余多余文本。
- 用途：①作为纠错的标准答案；②未命中片段时，用户从中快速定位复制粘贴。

### 4.3 需求三：批量处理

- 一部剧 = 一个剧本文件（含全部集）+ 每集一个 SRT 文件（文件名 = 集数）。
- 批量导入多集，自动定位集数，多集并行处理、互不干扰。

### 4.4 需求四：字幕拆分规则（已确认）

**背景**：剪辑师用剪映做字幕，剪映**不识别英文逗号 `,` 和句号 `.`**。此前靠 DeepSeek 网页对话手动改，效率低，故要求开发自动工具。

**完整规则**：

1. 只保留英文台词，删掉角色名、中文翻译、舞台提示。
2. 标点全部用**英文半角符号**：句号 `.`、逗号 `,`、省略号 `...`、叹号 `!`、问号 `?`、引号 `"`，每个标点占 1 个字符位（等同英文字母）。
3. 按语义和标点断句，每行尽量一个完整意群。
4. 每行 ≤ 23 字符（英文半角，含空格 + 标点，标点按 1 字符计）。
5. 超长时在逗号/连接词/介词短语/从句边界换行。
6. 不增删改词，只做换行。
7. 每片段最多 **2 行**（即每片段 ≤ 46 字符）。
8. 超过 2 行 → 拆成新的 SRT 片段，时间轴按字符数比例重分配。

### 4.5 需求五：UI 审查与导出

1. **差异标红**：每个片段保留原始/修正后文本，逐词 diff；修改与新增文本**红色标亮**，删除文本红色删除线。
2. **可撤销 / 手动改**：用户可改回原文或手动编辑。
3. **未命中处理**：从台词库（按集/场景定位）复制粘贴正确文本。
4. **拆分预览**：导出前在 UI 预览拆分结果（每片段拆成哪几行、是否拆新片段、时间轴分配）。
5. **导出**：保持源文件名，用户自选/新建文件夹，同名时确认是否覆盖。
